ModSync/For guide authors/CLI reference

CLI reference

Every command and option of the modsync command line, grouped by the job you are doing. For a short overview, read Command line. Run modsync --help or modsync <command> --help to see the same list in your terminal.

Global options and conventions

These options work with any command. Put them before the command name, for example modsync -v validate ....

OptionWhat it does
-v, --verboseAdds diagnostic log lines on stderr. Structured output on stdout stays the same, so scripts are not affected.
--plaintextUses plain text progress output. This is already the default for the command line.
-h, --helpShows help for the command you name, or for everything when no command is given.
-V, --versionPrints the version number.

Running modsync with no command opens the desktop app, the same as modsync gui.

Exit codes

CodeMeaning
0The command finished and succeeded.
1The command failed. A message starting with Error: is printed on stderr. A validation report that does not pass also exits with 1.
130The command was cancelled, for example with Ctrl+C. Maintenance that was cancelled and rolled back also uses 130.

modsync holopatcher passes the exit code of the patcher backend it ran.

Output formats

  • Most commands print plain text by default.
  • Commands with --json print one JSON document. Some print a single pretty-printed document, and some print one JSON event per line (called newline-delimited JSON). Each command's section says which.
  • install --install-progress-json prints typed progress lines on stdout. The last line has "phase": "completed" on success.

Hidden options. A few options exist only for testing and do not appear in --help. They are not documented here, and you do not need them.

Installing

These commands read a guide, check it against your game and mod folders, and install it. Most of them share the same set of options. Start with list and validate before you run install.

list

Lists the components in a guide, with their download links, as JSON.

modsync list <input>
ArgumentValueWhat it doesDefault
<input>fileThe guide to read. Required.None

Example:

modsync list KOTOR1_Full.toml

Validate, install and conflicts

validate checks a guide without changing anything. install validates, takes a snapshot of both folders, and then installs in order. conflicts reports game files that more than one component writes. All three accept the same options, so the table below covers them together.

modsync validate  --input <guide> --game-dir <folder> --source-dir <folder> [options]
modsync install   --input <guide> --game-dir <folder> --source-dir <folder> [options]
modsync conflicts --input <guide> --game-dir <folder> --source-dir <folder> [options]

Options marked validate only are refused by install and conflicts. Options marked install only are refused by validate.

Examples:

modsync conflicts --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods

Patchers

Patcher steps run a program, so they need your permission. Use --allow-processes on install, or the explicit trust option on the commands below.

Runs a HoloPatcher backend on its own, outside a guide install. You can use it to test a patcher run. Nothing is checked against a guide.

modsync holopatcher --patcher <program> --allow-processes [options] [-- <backend arguments>]
OptionValueWhat it doesDefault
--patcherfileThe HoloPatcher program to run.None
--allow-processesnoneLets the program run with your user permissions. Required.Off

--working-directoryfolderThe folder the program starts in.None
--timeout-seconds1 to 86400Stops the program after this many seconds.3600
-- ...argumentsPasses everything after -- to the program unchanged.None

Guides: convert, merge and drafting

These commands read, change, compare and save guide files. They never install anything. Guides can be TOML, JSON, YAML, XML or Markdown.

convert

Converts a guide to another format. It can also draft instructions from a Markdown guide, or generate instructions from archives you already have.

modsync convert <input> <output> [options]
modsync convert --stdin --format yaml < guide.json
OptionValueWhat it doesDefault
<input>, -i, --inputfileThe guide to convert. Give it as a position or with the flag.None
<output>, -o, --outputfileWhere to save the result. If left out, the result is printed to the terminal.Terminal
--stdinnoneReads the guide from standard input (up to 8 MiB). Cannot be used with an input file.Off
-f, --formattoml, json, yaml or xmlThe format to write.toml
--parse-directionsnoneDrafts instructions from the written directions. Generated steps must be reviewed before you install.Off
--review-draftcomponent GUIDMarks a component's drafts as reviewed. Repeat for more components.None
--review-verified-draftsnoneMarks drafts as reviewed only when a fresh check of the matching local archive gives the same result. Needs --source-path. Prints a JSON summary on stderr.Off
--ignore-errorsnoneSorts components even when an install-before or install-after reference is missing, instead of stopping.Off

Also accepts the options in Shared processing options.

Downloads and sharing

These commands download archives, check them, and share them through BitTorrent. Downloaded archives are checked before they are saved. An existing file is never overwritten.

Privacy options for BitTorrent commands

These options apply to torrent-seed, torrent-download and torrent-inspect. Peer traffic goes through a SOCKS5 proxy by default, so peers see the proxy's address instead of yours. The proxy operator can still see your traffic.

OptionValueWhat it doesDefault
--peer-proxysocks5://IP:PORTA SOCKS5 proxy for every peer and tracker connection. Repeat to add fallbacks.None
--peer-proxy-list-urlURL, or ""A public proxy list to try when none of your proxies work. Pass "" to turn this off.The monosans proxy list
--tracker-list-urlHTTP or HTTPS URLA tracker list to use. Repeat for more lists.The ngosang HTTP and HTTPS lists
--no-proxynoneConnects to peers directly. Peers can see your IP address. Opens a listening port, and uses DHT and UPnP.Off
--upload-kibpsKiB per second (16 or more)Caps how fast you upload while sharing.100
--no-upload-while-downloadingnoneDownloads from peers without uploading to them.Off
--share-hourshours (0 for no limit)Stops sharing after this many hours. Used with --authored-magnet.24
--share-ratioratio (0 for no limit)Stops sharing once you have uploaded this much compared with what you downloaded. Used with --authored-magnet.1.0

With no working proxy, the command stops. It does not connect to peers directly. Use --no-proxy only if you accept that peers will see your IP address.

download

Downloads one archive over HTTPS and checks it before saving. A web page, a damaged archive, an unsafe file name or a checksum mismatch makes the download fail.

modsync download <url> <output> [options]
ArgumentValueWhat it doesDefault
<url>HTTPS linkThe archive's address. Required.None
<output>fileWhere to save the archive. Required. Existing files are not overwritten.None
--source-dirfolderYour mod folder. Coordinates nested outputs with installs and maintenance on this folder.None

This command works with direct HTTPS links to ZIP, 7z, RAR, TAR and GZip files. Nexus Mods and DeadlyStream pages, and MEGA links, are downloaded in your browser instead.

Common recipes

These short workflows combine the commands above.

Validate in a script and read the result

Use this when another program needs to decide whether a guide is ready. Validation prints a JSON report. The command exits with 1 when the report does not pass.

  1. Run validation with JSON output, and save the report to a file.

    modsync validate --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods --output json > report.json

  2. Check the exit code. 0 means the report passed, and 1 means it did not.

    if modsync validate --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods --output json > report.json; then
  echo "Guide is ready"
else
  echo "Guide has problems, see report.json"
fi

  3. Read the success and errorCount fields in report.json if you need details.

Install only some components

Repeat --select for each component you want, and --option for each option. Repeating the flag is safer than listing many values after one flag, because the list ends at the next flag.

  1. Check the names and GUIDs first with list or selection.

    modsync selection --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods --select "Some Mod" --select "Another Mod" --json

  2. Validate the same selection.

    modsync validate --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods --select "Some Mod" --select "Another Mod" --option OPTION_GUID

  3. Install with the same options.

    modsync install --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods --select "Some Mod" --select "Another Mod" --option OPTION_GUID

Recover after a failed install

When an install stops, the folders are not left half-changed. Restore them first, then fix the cause and run again.

  1. Put both folders back to the snapshot from before the install.

    modsync restore --game-dir /path/to/game --source-dir /path/to/mods

  2. Fix the cause that the error message named, such as a missing archive.

  3. Validate again, then install from the start of the guide. Do not add a failed mod to the end of a run.

    modsync validate --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods
modsync install  --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods

Install from a saved profile

Save your setup once, then reuse it. Explicit options you add still override the profile.

modsync profile --action capture --name "Full Build" --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods
modsync profile --action activate --name "Full Build"
modsync validate --active-profile
modsync install --active-profile

See which files clash before you install

The conflicts report lists every game file written by more than one component, in install order. Use it to decide which mod should win.

modsync conflicts --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods > conflicts.json

Check a download against a known hash

Give --sha256 with the hash from the guide. A file that does not match is not saved.

modsync download https://example.org/mod.zip /path/to/mods/mod.zip --sha256 EXPECTED_HASH
