Your first full build

A step-by-step walkthrough for installing a full KOTOR mod build for the first time. Follow the steps in order and you will end up with a working game.

Before you start

A full build is a long list of mods that install in a set order. Spend a few minutes getting ready. It saves a lot of trouble later.

  • A clean game install. Build instructions assume a fresh game. If you installed mods by hand before, uninstall and reinstall the game first.
  • The right game version. Each build's guide says which game and release it is for. ModSync looks at your game folder and shows what it found under Settings > Game Installs, as Game found in this folder. For KOTOR 2 it can tell the Aspyr release apart from the others. Mods marked Aspyr only are skipped when your game is not the Aspyr release.
  • A backup. Copy your game folder somewhere safe before your first big install. The restore point ModSync makes is there to undo a failed install. It is not a copy to keep.
  • Free disk space. ModSync keeps the downloaded archives, unpacks them while it works, and keeps a restore point of your game folder. Pick a drive with plenty of room in Settings > General.

Read the build guide's notes. A mod's details show the build's notes and Compatibility notes. Read them for the mods you pick, especially the Aspyr notes for KOTOR 2.

Get the instruction file

The KOTOR Community mod builds published at kotor.neocities.org are already in the desktop app's list of builds, so for those there is nothing to download. The app fetches the latest version of the build when you pick it.

For any other build, either add its guide's web address with Add build, or download its instruction file and open it with Open file. The instruction files for the community builds are also in the public repo at kolto-labs/mod-builds, which is where you get them for the command line.

The instruction file tells ModSync which mods are in the build and how each one installs. ModSync reads TOML, JSON, YAML, XML and Markdown instruction files. It does not come with any mods.

Download the mods

Most KOTOR mods are on DeadlyStream or Nexus Mods. In the desktop app you do not have to download them one by one: Check downloads the files for every mod you picked into your Download folder, and keeps the ones you already have.

  • DeadlyStream: works without an account where the site allows it. Some files need you to be signed in. Sign in under Settings > Account.
  • Nexus Mods: add your Nexus API key under Settings > Account. With a free account, the app asks you to click Mod Manager Download on each mod's Nexus page and catches the link. Premium accounts download without the clicks.
  • Everything else the app cannot fetch is listed with a link. Download it in your browser and put the archive in that mod's download folder (Open download folder opens it), then check again.

Keep the file names as they are, and do not unzip or rename the archives unless the guide tells you to. ModSync opens archives itself.

On the command line, put every archive in one mod folder, separate from your game folder. modsync fetch-downloads fetches the ones it can, and modsync download handles a single direct link, as shown in the command line guide.

Open ModSync and pick the build

Open the desktop app. If you still need to install it, see Getting started. The first time, the setup steps help you find your game, sign in to DeadlyStream and add a Nexus key. Each step can be skipped.

  1. Go to Builds in the sidebar.
  2. Choose your build from the list at the top, for example the KOTOR 1 Full Build.
  3. Click Refresh list to fetch its latest mod list. The mods appear below with a summary of how many there are and how many are installed.

The Desktop app page describes every screen in more detail.

On the command line, you can list the mods in a guide before you install anything:

modsync list KOTOR1_Full.toml

Choose your game and mod folders

  1. Game folder. Under Settings > Game Installs, the app lists the KOTOR installs it found on this computer. Click Use this install, or click Add install and choose the folder that holds your game and its Override folder. Set active picks the one to install into. If no install is set up, the app asks you for the game folder when you first check a build.
  2. Mod folder. Under Settings > General, Download folder is where mod archives are kept. Keep it separate from your game folder.
  3. Folder for unpacking mods (optional) is where archives are unpacked while checking and installing. Leave it empty to use your system's temporary folder.

The two folders must not overlap. ModSync refuses a game folder and a mod folder that overlap, and it refuses paths that point outside them.

On the command line, these are the --game-dir and --source-dir options, shown in the steps below.

Pick mods and options

On the Builds screen, tick the mods you want. Select all and Select none help with a long list, and the count above the list shows how many you have picked.

Click a mod, or View details, to see what it is before you install it: its page description and screenshots, the build's notes, and the steps the installer will take. The details also show:

  • Options, extra choices such as a texture or a tweak you can turn on. Options keep the defaults the guide sets.
  • Needs these mods, the other mods this one depends on. Select those too.
  • Cannot be combined with, mods the build says not to install alongside it.

Spoiler-free mode under Settings > General swaps in names and descriptions without plot details, where the guide provides them. It only changes the text you see.

Only download widescreen files for my screen, also under General, downloads only the widescreen files that match the monitor the app is on.

Some mods have their own installer questions. The check lists those under Installer choices.

On the command line, ModSync selects every top-level mod by default. To pick your own mods, use --use-file-selection or --select. The command line does not add dependencies for you, so select those yourself.

modsync validate --input KOTOR1_Full.toml --game-dir /path/to/game --source-dir /path/to/mods \
  --select "Mod Name" --option OPTION_GUID

Check the build and read the report

Click Check. The app downloads the files, works out the install steps, then walks through the whole install without changing your game. Nothing in your game folder changes yet.

Check results shows how many errors and warnings it found, grouped into Folders and settings, Mods that cannot be combined, Install order, Mod files and steps, Installer choices and Practice install. Use Go to first problem to jump to the first one, or Copy report if you want to share the report when asking for help. Install unlocks once the check passes.

  • Errors must be fixed before you install.
  • Warnings are worth reading. Check each one before you decide whether it matters.

These are the messages you are most likely to see, and what to do about them:

What you seeWhat it usually meansWhat to do
Missing required archive: ... or Missing Required Archives: [...]The guide expects an archive that is not in your mod folder, or the file has a different name than the guide expects.Download the missing archive into the mod folder, using the file name the guide shows. Then check again.
WARNING: ...: missing dependencies: ...A mod you picked needs another mod that is not selected.Select the mod it names, or deselect the mod that needs it.
Required dependency is absent from the guideThe guide itself is missing a mod it depends on.Ask the build's author. Changing the guide yourself is not recommended.
... is Aspyr-exclusive and cannot be selected for this gameThe mod only works with the Aspyr release of KOTOR 2, and your game is not that release.Leave that mod off, or check that you have the right game version.
duplicate files/folders ... in a case-insensitive environmentYour game folder has two copies of a file or folder whose names differ only by capital letters. This often comes from an old manual install.Check the output for the names listed. Keep a backup, then remove the extra copy. If you are unsure, ask the build's author before you continue.
Some components failed to validateOne or more mods failed. The message suggests a missing download, or an antivirus program blocking ModSync or HoloPatcher.Read the lines under it. Fix the missing downloads first. If files are being blocked, allow ModSync in your antivirus.
Missing external program/mod or Patcher install log not foundA patcher step needs a program or file that is not set up yet.Set up the patcher as described in Allow patchers, then check again.

After you fix something, check again. A passing check is not a promise of a perfect install. Patchers run only at install time, so the check cannot tell you what they will do.

When a check passes, the Conflicts screen lists game files that more than one mod writes and which mod ends up being used, plus mods the build says not to combine. See Conflicts.

On the command line:

modsync validate --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods
modsync validate --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods --json
modsync conflicts --input guide.toml --source-dir /path/to/mods --game-dir /path/to/game

Allow patchers if the build needs them

Many KOTOR mods come with a patcher, a small installer program that changes game files. The desktop app runs those patchers for you.

  1. Under Settings > Patcher, Let mods run their patcher or installer is on by default, because most builds need it. Turn it off only if you want no program from a mod to run. Mods that need one then fail with a clear message.
  2. Patcher for TSLPatcher mods picks the program that applies these mods: OdyPatcher, HoloPatcher or KPatcher. Leave it alone unless the guide asks for a specific one.
  3. To use your own copy of a patcher, set Patcher executable under Custom patcher.

Only install builds you trust. A patcher a mod runs has your own user permissions.

Windows patcher programs need a Windows computer. ModSync does not run them through Wine for you.

On the command line, programs never run unless you add --allow-processes:

modsync install --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods \
  --allow-processes --patcher /path/to/odypatcher

Install and watch the progress

  1. When the check has passed, click Install. The button shows how many mods, for example Install 140 mods.
  2. If some mods come from Nexus Mods, the app reminds you about Nexus download limits, or about a missing Nexus key, before it starts.
  3. The app checks again, then installs the mods in the build's order. The progress bar and each mod's status update as it goes, and the Activity log records every step.
  4. When every mod is done, the summary shows them all as installed.

Pause holds the install at the next safe point, between downloads or between mods, and Resume carries on from there. Stop ends the run at the next safe point. Neither leaves a mod half-installed.

A mod marked Manual install required needs a step the app cannot do. Use Open folder and Show readme, follow the readme, then click Mark as installed.

On the command line, a single command validates, makes the restore point and installs. Add --pause-file to pause it from outside, as described in the CLI reference:

modsync install --input guide.toml --game-dir /path/to/game --source-dir /path/to/mods

If something fails

ModSync stops at the first failure and marks the install as unfinished. It will not start another install on top of a half-finished one.

  1. Restore first. The Builds screen shows a banner saying the install did not finish. Click Restore to put your game folder back to how it was before that install started. Restore checks the restore point before it touches anything, puts your files back, and then checks them again.
  2. Fix the cause. Most failures come from a missing or wrong archive. Read the check results and the messages in the table above.
  3. Start again from the top. Check, then install the whole build again in the guide's order. Retry failed is only for downloads that failed, such as a file you then fetched by hand.

Never add a failed mod to the end. Mods later in a build often overwrite or build on files from earlier ones. Installing an early mod last can undo later mods or break the game. Restore, then rerun the whole guide.

On the command line:

modsync restore --game-dir /path/to/game --source-dir /path/to/mods

For more on how restoring works, see Safety and recovery.

After installing

Launch the game and check that it starts. Try a few places where your mods change things, such as a new texture or a changed area.

The Installed mods screen lists everything installed in your game. You can turn a mod off there without deleting it. The restore point is not a backup, so keep your own copy of anything valuable, such as your save games.

If you add or remove mods later, run Check again before installing, so ModSync checks the new set of mods first.
