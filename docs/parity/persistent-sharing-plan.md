# Persistent finished-download sharing

Status: independently approved implementation contract, source-audited 2026-09-28. No sharing implementation or runtime acceptance is claimed. Fetch source2889ec5 has passed independent spec/quality review. This plan supplements p2p-acquisition-plan.md and downloads-gui-plan.md; it does not make the Rust port complete or discharge unrelated parity rows.

## Reconciled source and gaps

- `src/p2p.rs:326–365` already defaults sharing, keep_sharing and upload_while_downloading to true, Race and 100 KiB/s. `PeerSettings::policy` (459) gates sharing/mode before discovery, but does NOT gate keep_sharing before tracker-list fetch. A finished-share owner must check all three before calling it. Case-insensitive settings currently take the last matching key (370); conflicting case aliases can defeat Off and need normalization/conservative reading.
- `src/peer_acquire.rs:43–94,189–221` owns one lazily bootstrapped policy per acquisition run and calls fetch_authored only. It is not a persistent owner. `p2p::fetch_authored` stops its session (1395). Keeping this adapter alive alone does not seed anything.
- `src/download_orchestrator.rs:446–475` already returns TargetOutcome with target/component/URL/path/hash/source and a RunReport. Admission must use its accepted terminal report and captured plan/guide, not a Phase::Completed notification or the mutable current GUI guide. `AcquisitionPlan::single` (88) is Peer Off, so NXM must not accidentally enroll a share.
- `p2p::share_verified_authored` (1530) is an existing synchronous blocking primitive: exact authored identity, independent verified private copy, paused piece recheck, proxied sessions, cancellation and cleanup. It does NOT itself archive::verify; admission/restart must do that using captured archive options. It has no public progress callback. `ShareUntil::default` (1438) limits each invocation to 24 hours or ratio 1.0; repeatedly calling it currently resets those budgets.
- `ShareCopy` (1057), owner/root locks and sweep_stale_shares (1113) protect ephemeral engine copies across processes. Those locks do NOT establish persistent catalog ownership. Engine copies are removed on return. Never repurpose them as trusted durable downloads or bypass their read-write isolation.
- `share_authored` uses file length/mtime change detection (1552,1792), not continuous hash verification. The private copy is checked against the authored hash before use. Documentation must not claim every same-size/mtime source mutation is detected instantly.
- `proxied_session` (1207) disables listener/DHT/LSD and binds the SOCKS transport; `PeerPolicy` documents HTTP(S) tracker filtering (1155). Reuse this path exclusively. The explicit torrent CLI direct path remains separate; it is not a fallback for application sharing.
- `profiles::SettingsFile::{resolve,load,save}` (647–686) supplies explicit store resolution, preserving JSON and atomic owner-only save. Desktop initialization/isolation correction in downloads-gui-plan.md G10 is prerequisite. GUI and CLI currently have no application-lifetime sharing owner.

## Product boundary and ownership

Persistent means sharing survives a Fetch terminal, navigation and subsequent eligible runs while the application is open, and eligible records may resume after a deliberate desktop restart. It does not mean a daemon, service, autostart or networking after exit. Normal fetch-downloads must retain bounded command completion; it must durably enqueue each eligible accepted completion for the desktop owner before reporting enrollment complete, but does not wait 24 hours or fork a background process. A persistence failure is an explicit sharing-enrollment failure alongside the truthful acquisition result; it cannot be reported as successful enrollment. Existing torrent-seed remains the explicit foreground sharing command and maintainer authoring tool; no new authoring feature is required.

Create one small `src/peer_sharing.rs` owner, registered from lib.rs. It owns a versioned local catalog, one worker/join handle, cancellation, generation-tagged status, and an exclusive **worker-owner lock** per resolved settings directory. Do not hold the existing share-root lock or the catalog transaction lock for the owner lifetime. A second desktop process cannot start duplicate workers. All producers, including CLI and desktop, use a separate short transaction lock to publish one atomic pending-enrollment record per deterministic identity into a private spool. Use atomic replacement/no-clobber admission under that lock; a duplicate must preserve existing accounting and pause/exhaustion states. CLI enrollment succeeds even while the desktop worker owns its lifetime lock. The owner polls the spool at a bounded interval (one second while awake), consumes records idempotently into its catalog, durably commits the catalog entry, then removes the pending record. A crash before removal merely causes deduplication on replay. No general IPC or manual second Fetch is required; when no desktop runs, pending entries wait durably for its next launch. Settings Off blocks network/worker startup, not lossless pending-record consumption into paused state.

Use one active completed-share worker and a disk-backed round-robin queue, so the existing per-session upload limit remains the completed-sharing aggregate limit. State the limit as completed-sharing traffic: concurrent acquisition sessions currently each have their own cap; do not falsely advertise a global application upload cap. Give each ready identity at most a five-minute active-session quantum; advance earlier after 60 seconds without any increase in uploaded bytes. Stop/join the worker before moving the identity to the queue tail. A no-receiver identity becomes deferred for five minutes rather than spinning; other ready identities immediately get their turn. Verification/bootstrap does not consume the identity's sharing-duration budget, but must have bounded, cancellable attempt timeouts so a stuck preparation cannot monopolize the queue. Persist cumulative **active sharing duration**, measured monotonically between real transport-start and session-stop, and cumulative uploaded bytes. Queue wait, application downtime and deferred retry time consume neither budget. Never-started B cannot expire because A held the worker. Each invocation receives remaining duration/ratio; quantum cancellation is a scheduler transition, not a user Stop. Duration and ratio exhaustion are terminal and survive duplicate enrollment/restart. Resume preserves remaining budgets; it is not an implicit budget reset.

There is no arbitrary total-candidate limit. Keep only one worker and a bounded in-memory page (for example 128 records) over durable pending/ready entries; exceeding that page spills to disk, never rejects eligibility or discards a pending entry. Use per-identity files plus a paged cursor/index rather than loading the entire catalog JSON. Active queue records and retained history are distinct: finished/exhausted entries leave the ready queue and become compact identity/accounting/provenance tombstones, so history cannot occupy worker slots or prevent later enrollment. Tombstones preserve duplicate suppression, budget exhaustion and explicit pauses; do not garbage-collect them automatically in this slice. Disk-full or record-write failure is visible, keeps already durable pending records recoverable, and retries consumption after storage recovers; never acknowledge a nondurable enrollment. One engine copy bounds concurrent disk use; check space/copy errors and leave the source untouched. Queue identities deduplicate by normalized source root/path plus archive SHA-256 and authored infohash. Keep component/URL and captured guide provenance as separate authorization references; identical bytes with different infohashes remain distinct identities.

Catalog is local, private data, not guide metadata or a download receipt. Store canonical path/root, authored hash/magnet/info dictionary, archive options required for verification, provenance identity, eligibility state, cumulative active sharing duration, cumulative uploaded bytes, and explicit pause/terminal reason. Do not persist API keys, authenticated URL queries, proxy credentials or raw diagnostic responses. Bound each encoded info/record size and each in-memory load page; the number of durable records is not a product limit. Unreadable/malformed/unsupported catalog fails sharing closed with a visible reason, without defaulting to an empty trusted catalog or blocking Origin.

## Admission and identity

An additive shared admission helper takes captured guide/plan plus authoritative report. It never changes Acquire, Acquired, RunReport or existing serialized contracts solely to fit this feature. Require noncancelled accepted context, Completed outcome, actual final path within captured root, exact match to authored SHA-256, and guide-authored eligible magnet. Include Origin, Peer and verified Existing outcomes equally. Skipped metadata alone is not verification: re-verify a present skipped file through production verification before admission. No Manual/Failed/Cancelled outcome, race loser, utility download without authored metadata, NXM single plan, or observed hash can authorize sharing. Conservatively do not enroll successes from a cancelled batch until a fresh accepted verification.

Validate metadata before policy/discovery: single safe archive name, supported infohash, decoded TorrentInfo hash and single-file shape; reject malformed present TorrentInfo. If absent, retain the primitive's rebuild-and-compare behavior, never mint a replacement swarm. Call archive::verify and hash the actual candidate, then let share_verified_authored independently verify/copy/recheck the pieces. Never pass race staging paths to the owner. No socket or sharing policy bootstrap before eligibility checks and effective settings checks. A guide change withdrawing fields invalidates matching known provenance; do not infer permission from a cached computed hash. On restart, require revalidation of saved guide provenance against its current local guide before automatic resume. Unsaved/in-memory guides can share during that process, but persist as requires-revalidation and do not auto-resume after exit. Missing or changed guide provenance pauses the record visibly. Never scan unrelated folders to manufacture eligibility.

## Lifecycle and privacy

States are queued, verifying, sharing, stopping, paused, finished and failed. Events carry owner generation plus candidate identity; UI projection rejects stale generations. Acquisition reports and sharing statuses remain distinct. A Sharing row requires a real started callback from production transport; queued does not mean uploading. A transfer counter must come from actual engine statistics.

- Fetch terminal may enqueue after accepted recording/context checks; it returns independently of sharing. Admission/persistence failure appears as a sharing failure, not an invented download failure.
- Downloads Stop cancels acquisition and completed sharing, waits for both owned workers, then presents settled terminal state. Persist a user-stopped pause so repaint, another successful Fetch or restart cannot silently requeue those same entries. Expose a small explicit Resume sharing action. New independently admitted identities remain subject to current settings.
- Global Sharing Off remains accessible in Settings/status while acquisition controls are otherwise disabled and takes effect immediately, even during acquisition: persist Off, cancel the active acquisition as a whole through its existing cancellation contract plus the sharing worker, and await cleanup. This avoids adding unsafe mid-race source surgery. KeepSharing Off stops only completed sharing; it does not disable acquisition uploads. Mode Off also suppresses finished sharing to match current policy(). Other peer settings controls retain the desktop plan's next-run behavior and remain disabled during active acquisition; apply edited settings only to a new worker after the old one stops/joins. Do not mutate live policy in place. Preserve unrelated keys/secrets and collapse case aliases so false/Off cannot be overridden.
- Install/restore/profile or root mutation requires a sharing pause barrier: cancel and join workers before engine access or changed ownership. Keep acquisition gating from the GUI plan. After the engine operation, keep records paused until fresh hash/archive/provenance validation, then resume only if not user-paused or globally off. Never let a sharing terminal mark installation successful, validated or rolled back.
- Exit confirmation mentions both downloads and sharing. After confirmation cancel/join, persist accounting and reasons, remove private copies, release locks, then close. No detached worker or background process. Cancellation during slow verification/copy/bootstrap must remain visible as stopping; audit those blocking sections and add cancellation-aware production helpers where necessary. Never claim bounded shutdown from an AtomicBool alone.
- Restart loads effective settings and acquires catalog ownership before any network. Sweep only stale owned temporary copies with the existing primitive. Revalidate each candidate's path, authored identity, archive and provenance. Resume only eligible non-user-paused entries with remaining budget. Preserve cumulative active sharing duration (24 hours total), cumulative ratio (1.0), and terminal exhaustion across restart; queue wait/downtime do not age out entries. Repeated Fetch, duplicate pending enrollment and Resume never reset these budgets. Exhausted entries stay exhausted; a separate budget-reset product feature is outside this slice. Before starting each worker durably mark it in-flight; unclean restart pauses that record pending Resume rather than guessing lost upload accounting.
- A dead proxy pauses/defer-fails sharing with its typed reason and leaves Origin usable. Do not busy-loop rebuilding policies or re-fetching lists: retry on explicit Resume or next application startup, with the same remaining budgets. Proxy failure during a session may use the existing bounded rotation only. No direct networking fallback, inbound listener, DHT, LSD, UPnP or UDP trackers. Discovery list HTTPS requests are ordinary bootstrap traffic and must be disclosed separately from peer/tracker SOCKS traffic; proxy servers themselves know the client's address. Do not claim anonymity from proxies or public-list providers.

Two outbound-only proxied clients cannot necessarily meet. A reachable peer with the authored torrent is required. Prove the negative case and label waiting/no reachable peers accurately; do not imply a relay, NAT traversal or universal user-to-user reachability was implemented.

## Exact production acceptance boundary

Use the accepted loopback transport and desktop isolation plans, real production CLI/desktop binaries, private Xvfb and disposable HOME/XDG/settings/guide/mod/game trees in an isolated network namespace. No real-host traffic, default KDE session, existing live installs or synthetic UI messages. Set public list URLs to null/empty and telemetry off in fixture settings. Use the reviewed local TLS Origin, recording SOCKS relay and a reachable production torrent-seed peer plus a receiving production torrent-download client. Where the receiver needs a listening socket to accept the proxied seeder's outbound connection, use only its explicit --no-proxy fixture mode inside the isolated network; the product under observation must always remain proxied. Verify fixture reachability first without silently weakening product policy.

Capture exact commands/actions, source revision and dirty-source manifest, binary hashes, fixture/settings hashes, packet capture, process-owned connect/send/listen traces, proxy/server logs, actual uploaded/downloaded counters, archive hashes, catalog snapshots and private-copy/root manifests. Native screenshots corroborate presentation only. Retain these under docs/parity/persistent-sharing/ without real mod names or secrets.
