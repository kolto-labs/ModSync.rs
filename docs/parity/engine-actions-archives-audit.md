## F04 component and option model differential

### Source findings

1. Rust deserializes `IsSelected` with the ordinary Boolean default `false`, but if every top-level component is unselected it selects every top-level component after parsing (`src/model.rs:34-59`, `src/model.rs:178-203`). The compatibility ledger identifies this as matching the reference loader for the all-unselected case (`docs/parity/ACCEPTANCE.md:90-98`). This is loader behavior, not proof of GUI, CLI, or direct-object defaults.
2. Rust recursively collects selected option GUIDs only beneath selected parents (`src/model.rs:303-317`). A reached `Choose` validates every authored option GUID, then executes selected matching options in declared order (`src/engine.rs:1098-1123`, `src/engine.rs:1331-1350`). C# `GetChosenOptions` applies the same selected-plus-source-ID predicate in declared option order (`src/ModSync.Core/Instruction.cs:1607-1611` in the pinned C# checkout).
3. Rust component and instruction conditions are case-insensitive GUID membership checks (`src/engine.rs:1056-1096`). C# computes conflicts from typed GUID dependencies/restrictions and selected components (`src/ModSync.Core/ModComponent.cs:1994-2028` in the pinned C# checkout).
4. Rust topological ordering treats `Dependencies` as predecessors and adds `InstallAfter`/`InstallBefore` edges while retaining guide order whenever the graph allows (`src/model.rs:319-390`). C#'s dedicated resolver builds only `InstallBefore`/`InstallAfter` graph edges (`src/ModSync.Core/Services/DependencyResolverService.cs:234-270` in the pinned C# checkout); ordinary component dependencies are checked separately at execution (`src/ModSync.Core/ModComponent.cs:1994-2007`). This is a likely semantic difference, not an accepted parity claim.
5. Rust stores untyped component fields in `metadata` (`src/model.rs:56-58`) while C# exposes typed `WidescreenOnly` and nullable `AspyrExclusive` properties (`src/ModSync.Core/ModComponent.cs:784-815` in the pinned C# checkout). Rust game gating reads metadata separately, so serialization presence does not by itself prove typed/default/game-selection parity (`COMPATIBILITY.md:104-106`).

## F07 CleanList and texture-priority differential

### Source findings

- The Rust CleanList selection helper mirrors the C# mandatory prefix, exact/substring shortcut, token stop list, crude plural stripping, and two-token/60% threshold (`src/engine.rs:1735-1775`; pinned C# `src/ModSync.Core/ModComponent.cs:1673-1778`). This is high-confidence source equivalence, not final-tree evidence.
- Rust splits each physical line again on carriage returns, accepts only rows with at least one comma, and treats every later comma-separated field as a relative filename (`src/engine.rs:1521-1542`). C# reads the complete file, splits CR/LF with empty entries removed, and applies its own row parsing (`src/ModSync.Core/Instruction.cs:674-786` in the pinned C# checkout). Encoding, quoting, duplicate field, and malformed-row equivalence remain unmeasured.
- C# defaults compatible texture extensions to `Game.TextureOverridePriorityList` (`src/ModSync.Core/Instruction.cs:588`), which is `.dds`, `.tpc`, `.tga` in that order (`src/ModSync.Core/Data/Game.cs:11`). Rust defaults to only `.tga` and `.tpc` and lacks `.dds` (`src/engine.rs:1488`). The ledger requires texture extension priority, not merely TGA/TPC behavior (`docs/parity/ACCEPTANCE.md:42`). The plan ports the list now as U0; F07-E only confirms it.
