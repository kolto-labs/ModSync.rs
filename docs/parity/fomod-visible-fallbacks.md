# F15 visible fallback diagnostics

The current source already checks registered-only archives against complete
current choices and mapping. It explicitly rejects C# configured prompt markers
without Rust choices. Those older remaining-plan items are implemented source,
with runtime interoperability evidence still separate.

The fallback diagnostic correction exposes file/game dependencies treated as
satisfied, unsupported/unattached conditional patterns skipped, and destination
rename fallback through the existing FOMOD validation warning list. Plain
validate/install receive warning events; structured validation and native
readiness receive counted FOMOD-stage warnings. Mapping behavior is unchanged.

The shared collector retains at most 64 distinct rendered warnings plus one
omission summary. Authored fields are limited to 256 Unicode scalar values before formatting;
each final diagnostic is limited to 1,024 scalar values with controls converted to spaces and an ellipsis when truncated. The
same final limit applies to the aggregate engine gate. Omitted counts represent
warning occurrences; omitted identities are not retained in an unbounded set.

The FOMOD editor caches shared fallback warnings when inspection completes and
shows them in a visible, bounded scroll panel before Finish. Warnings do not
select options, supply choices, or authorize installation. The existing choices
validation and explicit confirmation remain authoritative.

This is source implementation and static review scope only. No tests, archive
corpus, native UI execution, installation, or CI were run for this correction.
