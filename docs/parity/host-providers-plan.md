A concrete Nexus encoding difference also deserves a bounded correction: C# escapes the nxm key at `NexusModsDownloadHandler.cs:590`; Rust formats the raw key into the query at `src/updates.rs:283-286`. Reserved characters must retain their credential value, not become extra query parameters. This finding is from source, not an observed live exploit or test result.

A separate Nexus credential-confinement defect is visible in source: `src/updates.rs:165-171` gives `NexusClient::new` the default redirect policy, while `with_base_url` alone installs an origin-confining bounded policy at 177-191. `request` attaches the custom `apikey` header at 408. The locked reqwest 0.12.28 source, `src/redirect.rs:239-250`, removes standard Authorization/Cookie-related headers on cross-host redirects but does not remove `apikey`. The default constructor therefore lacks the override’s credential-confinement guarantee. This is a source finding, not evidence that the real Nexus API issues such redirects or that a credential has leaked.

Manual boundaries have different meanings. `src/acquisition.rs:25-40` makes LoginRequired, Captcha, FreeUserWait and HtmlLanding terminal gates; only Unsupported permits eligible Peer fallback. Preserve that distinction. No API key, a known free account, payment restriction, actual login, or an actual challenge must not be converted into an acquisition success or a peer workaround. An unimplemented anonymous provider remains Unsupported until implemented; it must not be relabeled LoginRequired without evidence.

### H3 — MEGA anonymous single-file decryption

Owner: MEGA-specific module plus the existing orchestrator origin branch, narrow CLI fixture seam, and dependency manifest/lock only if a reviewed client is selected. Keep shared publication and cancellation ownership with the existing orchestrator.

First bounded decision: inspect available MEGA client dependencies and choose a supported decrypting client/SDK based on actual single-file support, license compatibility, maintenance evidence, cancellation, streaming authentication/integrity, progress and endpoint injection needed for controlled proof. That review has not occurred here; no particular crate is endorsed. If no candidate meets the contract, record this as an implementation blocker and keep F13 partial. Metadata-only success or permanent Manual(Unsupported) is not completion of this slice.

Contract: support current and legacy single-file link syntax with fragment key; anonymous session/node resolution; decrypt node attributes and streamed file bytes using the supported client; validate integrity before final publication; expose safe node filename, size and supported metadata; honor cancellation and archive limits; clean all staging. Missing/invalid key, authentication failure, quota/access restriction, deleted node, corrupted attributes/ciphertext and truncated transfer must remain distinguishable failures/manual requirements, never successful empty archives. Fragment keys are secrets and must be redacted from retained diagnostics. Folder traversal remains unsupported unless separately justified by a public C# behavior and approved scope.

Controlled production proof must execute the selected production MEGA client and its actual decrypting stream against a synthetic protocol endpoint and encrypted synthetic archive. Use a known plaintext archive with independently retained expected hash, two link syntaxes and a valid encryption/integrity vector. Assert final plaintext archive hash, archive contents, progress, metadata and cleanup. Wrong key, altered ciphertext/MAC, bad node attribute name, missing node, quota/auth response and cancellation must publish nothing. A mock that returns a plaintext download URL, an already decrypted stream, or metadata is not evidence of MEGA parity. If the SDK cannot target a constrained local endpoint, that proof requirement remains unresolved; do not substitute fake success.

Any MEGA fixture endpoint override is provider-specific, explicit and invocation-scoped with the same loopback confinement, trust and no-stored-secret contract as H2. Review the SDK's secondary endpoints so no control/CDN request can escape the namespace. This is the only reason to add an endpoint seam; do not create a generic plugin system.

Live host acceptance is a later, separately authorized operation, not implicit in this plan or local fixture success. For Nexus, it needs authorized premium/keyed-account behavior and actual resulting archive bytes; for DeadlyStream, a permitted anonymous session/selection/download; for MEGA, a permitted encrypted public single-file download verified as plaintext; for Direct, a permitted actual downloadable resource. Actual login, CAPTCHA, timer, quota and payment restrictions are reported as boundaries requiring the appropriate user action or entitlement. Browser automation cannot be claimed to bypass them. Do not solve a CAPTCHA or substitute peer acquisition around a detected gate. Host layout drift, missing entitlement or an inaccessible artifact can block live proof without erasing independently demonstrated local functionality. GameFront has no autonomous live-download acceptance requirement under this C# baseline; verify its manual public contract separately.
