## Compatibility decisions that precede edits

1. Preserve reference scope, not an imagined complete FOMOD standard. C# parses `priority` but `Map/CreateCopyInstruction` do not sort by it; Rust stores it but executes authored/attachment order. Both use dependencyType defaultType only. C# treats file/game dependencies as true with warnings; Rust uses `FlagCondition::Always`. Neither is evaluating actual game/file state. Add visible bounded diagnostics for these fallbacks where needed; do not claim full dependency evaluation. Group/plugin ordering attributes, module dependency enforcement and dynamic type patterns are not implemented by the inspected reference parser either. Implementing them is separate scope, not prerequisite duplication.
2. Conditional attachment is intentionally restricted: flat flags bind to the first plugin satisfying all flags; unsupported nested/multi-Or patterns skip. Rust `selected_files` currently reproduces skip behavior, despite older FOMOD.md prose saying unsupported mapper patterns reject. Reconcile that stale statement when this slice is accepted; do not infer current behavior from that prose. Measure each source-to-file mapping quirk through production fixtures and record a deliberate compatibility decision before accepting it; matching a C# bug is not permission to silently skip semantics the product claims to support. Preserved fallback behavior must expose a diagnostic, and unsupported claimed behavior must remain explicitly partial or reject. Existing oracle directories cover bounded cases only.
3. Preserve safe divergences: never bypass Required through exclusive sibling selection; reject ambiguous archive/config/choice identities and unsafe paths; fail on corrupt archives. C# tolerates cases Rust rejects (first matching duplicate names, unknown plugin names, unchecked choices version); keep explicit failure and document it. Duplicate plugin entries currently collapse into one selected index: specify that as idempotent, not accidentally “duplicate rejection.”
4. Resolve Unicode names with a shared matching policy matching C# OrdinalIgnoreCase for supported input; do not substitute locale-sensitive folding or claim ASCII comparison suffices. Use actual CLI fixtures with non-ASCII archive/step/group/plugin names and case variants. If exact matching is deferred, list it as a retained gap and keep F15 partial.
5. Prompt status alone never authorizes installation. C# configured status can pass with only a missing-instructions warning; Rust explicitly requires choices. Preserve the stronger gate and make import/recovery actionable. A standalone metadata entry, saved status, mapped JSON or successful download is not proof of installed bytes.
6. Existing sidecar means version-1 choices JSON, not a separate new daemon or sidecar process. Preserve `fomod-inspect` and `--fomod-choices`. Do not add an automatically guessed adjacent sidecar filename: the inspected C# resolver uses explicit CLI/environment paths.

Ownership: `src/main.rs` CLI arguments and dispatch after acquisition; a narrow new `src/fomod_cli.rs` or `src/fomod/cli.rs` policy/helper module plus its library export if necessary; additive scoped application and cancellation-aware prompt helpers in `src/fomod.rs`; narrow shared follow-up collector/additive consumer binding in `src/download_orchestrator.rs`. Preserve existing public callers and the desktop contract's captured-context ownership; coordinate shared collector changes with its owner before editing. No acquisition adapter/transport rewrite, no UI changes, no engine behavior changes in this slice.

Add to `fetch-downloads` the existing C# public spellings `--fomod-skip`, `--fomod-choices`, `--interactive`, `--non-interactive`. Preserve existing Fetch JSON fields and apply the explicit result table below to every mode, including bare Fetch. Read `fomodPostDownloadMode` from the explicitly selected settings context, without overwriting settings or secrets. Resolve once before dispatch:

- Explicit skip wins over choices and mode sources.
- Otherwise explicit nonempty choices path wins over `MODSYNC_FOMOD_CHOICES`; load/validate the file before prompting or changing the guide.
- Otherwise nonempty settings mode wins over `MODSYNC_FOMOD_POST_DOWNLOAD_MODE`. `skip` wins over forced interactive; `warn-continue` applies after forced interactive; unrecognized mode falls through to terminal capability, as pinned C# does.
- Forced interactive selects interactive; otherwise `--non-interactive` disables automatic TTY choice; otherwise both stdin/stdout terminal capability selects interactive, redirected I/O selects warn-continue. Reject simultaneous explicit interactive/non-interactive flags before acquisition. This is an intentional clarification of C# resolver's force-interactive precedence over its terminal helper.
- Prompts and warnings stay on stderr; stdout remains valid existing summary JSON or progress envelopes. Forced interactive redirected stdin must terminate on EOF/cancel, not hang or silently choose defaults.

Extend the existing shared follow-up collector with additive consumer binding, preserving public callers and GUI captured-context rules. Enumerate every authorized eligible consumer from the captured acquisition scope before deduplicating archive inspection or a shared selection session. Current `download_orchestrator.rs:1758` inserts the path into `seen` before selection/prompt eligibility (`:1761–1768`): configured or warned consumer A can therefore suppress pending consumer B. Keep status and usable-configuration facts per consumer; deduplicate detection/session separately by archive identity. One valid shared session must apply atomically to ALL authorized pending consumers of that archive. Preserve configured consumers with valid prior choices; a suppressed consumer without usable choices stays unresolved in the result assessment. Never scan a second unrelated acquisition scope or mutate unselected, completed, unrelated or stale-context consumers. The component GUID plus archive path binds each mutation; do not blindly use `ChoicesFile::update_guide`, which writes choices to every noncompleted component. Both configured-first and pending-first, and warned-first and pending-first, must produce identical pending-consumer coverage.

Skip marks detected matching archives dismissed and warns; warn-continue marks warned and warns; both leave install blocked. Interactive asks configure now, then reuses the shared selection logic through an additive cancellation-aware sibling/adapter. Preserve the standalone `prompt_choices` API and behavior. The current `BufRead::read_line` blocks without a cancellation argument (`src/fomod.rs:795`); EOF/q are ordinary errors there, while Fetch uses `p2p::stop_signal_flag` (`src/main.rs:1554`, `src/p2p.rs:1979`), which only sets the flag. Consequently polling that flag between reads is insufficient. The Fetch adapter must cancel while waiting for a line without needing another input line and without leaving a detached blocked reader. Use typed outcomes: configured, refused, EOF, user-quit, signal-cancelled, and actual inspection/configuration/I/O error. Refusal leaves the current archive unresolved and may continue to the next; EOF/q stop further prompting and leave remaining archives unresolved; signal cancellation stops the run. None creates selected configuration. Choices mode applies the matching archive entry using existing atomic selection APIs. Only a fully valid mapped session records configured.

Extend summary additively with per-archive/per-consumer configuration outcomes and remaining unresolved configuration; preserve existing report/recordSummary/fomodFollowups fields. Assess usable configuration independently of `should_prompt`, including consumers suppressed by warned/configured status. Do not bypass known unresolved configuration by reporting acquisition success. Apply this precedence table after cleanup and emit one final summary even on signal cancellation:

| Highest applicable result | Exit | Required classification |
|---|---|---|
| Signal/run cancellation | 130 | Cancelled; no current half-session committed; earlier accepted sessions identified separately |
| Invalid saved choices, inspection/configuration/I/O error, or acquisition failure | 1 | Error, including suppressed configured/warned consumers with invalid saved choices |
| No error, but any consumer lacks usable choices or acquisition requires manual work | 3 | Unresolved, including suppressed warned consumers without choices, skipped/refused/EOF/q outcomes and remaining unconfigured sessions |
| Every authorized consumer resolved and acquisition has no remaining failure/manual work | 0 | Resolved success |

Thus warn-continue continues acquisition but cannot convert missing choices into exit 0. Distinguish absent choices (unresolved) from present invalid choices (error). Record the exit-contract distinction from C# host wording; prompt suppression is solely a prompting policy, never readiness proof.
